## medium: Published entrypoint points at an artifact this package does not build

id: fnd_sig-feat-config-7528cb5b98-6c26a_af1d8e1fdb
category: build-release
confidence: medium
triage: risk
status: open
feature: Project config package.json (feat_config_7528cb5b98)

evidence:
- package.json:6
- package.json:7-21 (scripts)

The package advertises dist/cli.js as its runtime entrypoint, but the configured scripts only run TypeScript directly with tsx or invoke quality/database commands. There is no build or prepack/prepublishOnly script in this config that would produce dist/cli.js before publishing or local consumption, so npm consumers can receive a package whose main entrypoint does not exist.

recommendation:
Add an explicit build script that emits dist/cli.js and wire it into prepack/prepublishOnly, or change main to an entrypoint that actually exists in the distributed package. If this is intended to be CLI-only, also define a bin entry and ensure the built CLI is included in the package.

test analysis:
No tests are linked for this feature, and the package test script targets src/**/*.test.ts rather than validating packed artifacts or package entrypoint resolution.

suggested regression test:
Add a release smoke test that runs the build, packs the package, installs/extracts the tarball in a temporary directory, and verifies the package main entrypoint resolves successfully.

minimum fix scope:
package.json scripts and package entrypoint metadata

repro:
From a clean checkout, run the package's release/pack workflow or install it as a dependency, then require/import the package entrypoint. Without an externally produced dist/cli.js, Node resolves package.json main to a missing file.

## medium: start script depends on dev-only tsx runtime

id: fnd_sig-feat-release-775032a0f4-3507_1a0c650bfe
category: build-release
confidence: high
triage: risk
status: open
feature: Package script start (feat_release_775032a0f4)

evidence:
- package.json:9 (scripts.start)
- package.json:38-43 (devDependencies)
- package.json:6 (main)

The package declares a compiled entrypoint at dist/cli.js, but npm start executes the TypeScript source through tsx. Since tsx is only in devDependencies, installs that omit dev dependencies, which is common for production or release environments, will not have the tsx binary available and npm start will fail before the CLI starts.

recommendation:
Make the release start path use a runtime artifact such as `node dist/cli.js` and add/verify a build step that produces it, or move `tsx` into dependencies if this package intentionally starts from TypeScript source in production.

test analysis:
No tests were linked for this package script, and the configured test command exercises TypeScript tests rather than a production install with devDependencies omitted.

suggested regression test:
Add a release smoke check that installs production dependencies only and runs the start command, or at minimum validates that `scripts.start` does not reference binaries declared only in devDependencies.

minimum fix scope:
Update package.json scripts and, if needed, package build metadata so `npm start` works in production/release installs.

repro:
Run `npm install --omit=dev` or `pnpm install --prod`, then run `npm start`; the script requires the dev-only `tsx` executable.
